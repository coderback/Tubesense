# Why Argon? gemini-4-argon vs gemini-3.8-flash on the same investigator task (post-hoc)

## Protocol (written 2026-10-25T04:04Z, before any comparison run; not edited after results)

**Question.** On the investigator task that produced the evidence pack, does gemini-4-argon do better
than gemini-3.8-flash when both are judged by the same deterministic verifier (agent/verify.py)? This
is a post-hoc engineering comparison, not part of the pre-registered sensor analysis.

**What is held fixed.**
- Code: `agent/investigator.py` unchanged except the new flags `--model`, `--out DIR`, `--no-atlas`.
  Same SYSTEM prompt, same response schema, same feedback message, `MAX_ROUNDS = 2` (up to 3 calls).
- Inputs: same corpus (`data/corpus/chunks.jsonl`, corpus_hash recorded), same section stats
  (`outputs_posthoc/section_stats.json`, hash recorded), same retrieval block. `--no-atlas` reuses the
  Atlas hybrid-search hits recorded in `outputs_posthoc/investigation.json` (CACHED; they were identical
  in all three earlier Argon runs) instead of querying Atlas, so the prompt is byte-identical across
  runs, and no claims are written to Atlas.
- `thinking_level = "medium"` for both models. No temperature or other sampling settings (Argon accepts none).
- Fresh runs only (no `--review`). Each run writes `outputs_posthoc/compare/<slot>/investigation.json`;
  the production `outputs_posthoc/investigation.json` is never written.

**Runs.** 4 per model, 8 in total, one at a time, in counterbalanced ABBA order:
argon, flash, flash, argon, argon, flash, flash, argon. Slot names `01_argon` ... `08_argon`.
- Transport/API errors (HTTP 429/5xx, timeouts, connection resets) are not model outcomes: the slot is
  logged and retried (at most 2 retries).
- Schema/parse failures (response is not valid Investigation JSON) are model outcomes: counted as a
  failed run, not replaced; the rounds completed before the failure are kept.
- If time and quota allow, a further ABBA block of 4 may be added; any block is added whole.
- Pilot (declared, not counted): one trivial structured-output call per model to confirm that both
  model IDs accept `thinking_level="medium"` with a response schema.

**Deterministic metrics, per run** (computed by `agent/compare_models.py` from the run records):
1. claims proposed in round 0 (the first response);
2. round-0 verifier rejections, as claims rejected and as reasons by category: quote not found,
   quote too short, unknown chunk, unknown stat key, missing citation/stat, unsupported number,
   banned phrasing, formula (sub-reason kept), other;
3. rounds used (1-3); converged = 0 rejections in the last round;
4. final verified claims, final dropped claims, asks, headline ids that survived;
5. seconds per round and in total (wall clock, includes network);
6. prompt / output / thinking tokens per round if `usage_metadata` reports them;
7. schema/parse failures and API errors.

Primary summary: round-0 rejection rate (rejected / proposed), final dropped, converged within the
round budget, total seconds. Everything else is secondary.

**Secondary check (single judge, clearly labelled).** The verifier cannot catch framing errors. I (the
comparison agent, Claude) will read each run's final verified claims and asks against the full text of
the cited chunks and record issues in the categories that the independent review found
(`pack_review.json`): out-of-context quote, overstated commitment, overgeneralised scope, other
misleading framing (e.g. phone levels set against TfL figures). Each issue is graded major or minor.
Blinding: `compare_models.py --blind` writes the claims of all completed runs in a shuffled order under
opaque labels (P1..Pn), with the key in a separate file that I do not open until every judgement is
written. Claim style or count may still reveal the model; this is a single-judge assessment, not
ground truth.

**Analysis.** Medians and ranges per model, plus every run's values. With n = 4 per model no
significance tests are reported; a difference is described as consistent only if every run of one
model is on the same side of every run of the other, and even then it is n = 4 on one task and one
day. Whatever the result, it is reported; if Flash does as well as or better than Argon, this file
says so and the "why Argon" argument must rest on something else or be dropped.

## Interpretation

_Written by hand after unblinding (2026-10-25); revised the same day after two independent reviews (deviation notes 3-9 and the README line). Post-hoc; n = 6 runs per model on one task, one corpus, one morning. The framing check is an unblinded single-judge assessment._

**Deviations from the protocol.**
1. A third ABBA block (slots 09-12) was added, as the protocol allowed. I decided this after slots 01-08 had finished and
   before looking at any result except each run's exit status and wall time.
2. The rule-by-rule framing table, the claim-content metrics and the sources table were added after unblinding. They
   are exploratory and were not in the protocol.
3. Blinding failed. The blind export kept each run's claim ids. All six Argon runs use the uppercase `C1` / `C01` style
   of the production Argon pack, which the judge had read; the Flash runs use slugs (`claim_1`, `c1`,
   `grind-records-2022`); and the checklist was built from `pack_review.json`, which cites ids such as `C03`. Claim length
   also differed, and checklist rule M is a known Argon signature. The key was written to the same folder as the export, so
   "key unopened while judging" rests on trust alone. The judge could most likely tell which model wrote each run: treat
   the framing check as an unblinded single-judge assessment. An earlier version of this note said the judge "did not know
   which group was which model"; that statement is withdrawn. For any rerun, `compare_models.py blind` now renumbers claim
   ids (K1..Kn) and the asks' references (ids of dropped claims and any other id-like token in the asks become K?), and
   `--key PATH` writes the key outside the judge's folder.
4. Judge bias: I built the checklist from the review of an earlier Argon draft (`pack_review*.json`), so it targets
   the errors Argon is known to make, and it does not count omissions (for example leaving out the Mayor's promise or the
   NO-GO verdict) as framing errors, except checklist items D and F. Both work against Argon. Knowing which runs were
   Argon could bias the judgement in either direction, so the net direction of bias is unknown.
5. Rescored after review. Rule M says the Pandrol Vanguard / Delkor error counts "also when carried into an ask", but
   `02_flash` ASK-3 ("confirming whether track replacement or Pandrol Vanguard conversion was executed") had been scored
   only as a minor overstatement. It now also counts under M as a major (hedged alternative, same attachment of PV
   conversion to the LST-BTH entry). Rule M's text now says what counts in an ask: stating or presupposing PV conversion as
   the content of that entry, hedged alternatives included; a neutral question about which fastenings are installed does
   not (`12_argon` ASK-2 was examined and not counted). The rescoring was done unblinded; the original scoring is kept in
   `compare/framing_judgements.json` (`rescored_after_review`). Effect: rule M reads 5/6 runs (Argon) vs 1/6 (Flash);
   Flash majors stay at median 0 [0-1].
6. The protocol cannot be shown to be unedited. The .md is untracked and `summarise` rewrites it (it keeps everything
   above "## Results" unchanged). What fits the claim that it was written first: it still says "4 per model, 8 in total"
   (deviation 1 adds the third block) and names a `compare_models.py --blind` flag that the code does not have (the
   command is `blind`; corrected here, not in the protocol text), and the first run (`01_argon`) started about 04:09:20
   (its log records the end at 04:11:02 after 100 s), later than the stated 04:04Z. A copy of the protocol section was
   frozen after the fact in `compare/protocol_frozen.md` (sha256 `5f1c9023...`, recorded in `model_comparison.json`); `summarise` now checks that the .md still matches it. That
   guards against later edits only. Committing these files to git would give the timestamp.
7. Judging depth. `blind_claims.json` was written at 04:33:26 and the judgements carry `written` 04:38:12 (the file was edited
   later for note 5), 4 min 46 s for 12 runs (169 claims and 40 asks). The notes in `framing_judgements.json` are the only record of how closely each item was
   read against its sources.
8. Rule D's text, reviewed 2026-10-25. It named the "< 1 dB" reason only, but `05_argon` C8 ("within limiter compression")
   had been scored major under it. The text now reads "any reason other than the reversed trip (e.g. size < 1 dB, limiter
   compression)", which is what the scoring already did. No score changed (`rules_clarified_after_review` in
   `framing_judgements.json`; unblinded).
9. The protocol's pilot (one trivial structured-output call per model, to confirm `thinking_level="medium"` with a response
   schema) left no record: no pilot output or `usage_metadata` is on file, so this file cites no pilot numbers. The 12 completed
   runs show that both model ids accepted the settings. The `method` field of `framing_judgements.json` and the `protocol`
   field of `model_comparison.json` were reworded so that they no longer say "blind" or "written before the runs" as facts
   (deviations 3 and 6).

**What the deterministic verifier shows: no difference.** Both models produced valid structured output in 12/12 runs,
used exactly 2 rounds, fixed every round-0 rejection, dropped nothing, and ended with 13-15 verified claims. Their
round-0 rejection rates overlap (Argon 0.21-0.47, median 0.31; Flash 0.07-0.33, median 0.28). Argon had more
quote-not-found rejections (12 vs 2 over all runs), and both had mostly unsupported-number rejections (27 vs 21).
Wall time was the same (median 107 s vs 110 s). On the verifier loop alone, gemini-3.8-flash did as well as
gemini-4-argon, so this loop gives no reason to need Argon.

**What differs: how much each says, and how it goes wrong.** Argon's verified claims are about twice as long
(51 vs 26 words), carry three times as many numbers, cite twice as many chunks (median 13 vs 6 distinct) but 1.5 times as
many documents (median 9 vs 6 distinct), and join two documents in one claim (0-4 per run; Flash never did). It also
uses more of the record. FOI-1730-1819 (the 2018 BTH-MLE
roughness FOI) appears in 6/6 Argon runs vs 2/6 Flash. The Aug 2024 TfL update appears in 5/6 vs 0/6. The Mayor's
16 Jul 2026 transparency promise, the item most relevant to the named user, appears in 5/6 vs 0/6. The pre-registered
loudness verdict is stated in 6/6 vs 1/6.

In the unblinded single-judge framing check, Argon runs had more issues per verified claim (median 1.00 vs 0.48), and
every Argon run was above every Flash run (0.77-1.13 vs 0.29-0.57), which meets the protocol's "consistent" rule. Argon
also had more major issues (median 3 [1-4] per run vs 0 [0-1]). Per 100 words the rates are about the same (median 1.86
vs 1.94), so most of the gap tracks how much each model says. Where the issues fall does differ:
- About half of Argon's major issues (9 of its 17) come from cross-document synthesis. In 5/6 runs it attached Pandrol
  Vanguard/Delkor from the 2024 update to the LST-BTH reconditioning entry in the 2022 letter (rule M), the same error
  the independent review caught (R01); Flash did so once, in a hedged ask (`02_flash` ASK-3, see note 5). The other 8
  majors are not cross-document errors: 6 gave the wrong reason for the loudness NO-GO (rule D, next bullet) and 2 turned
  the Mayor's "cannot see a reason why" on the eight-week programme into a commitment (rule H, R09; 2/6 runs).
- Every Argon run stated the loudness verdict, and every one gave a reason other than the reversed trip: five said
  "below 1 dB" (or "under 1 dB") and one (`05_argon`) said "within limiter compression". All six are scored major under
  rule D (note 8 widens the rule's text to cover the sixth). The stat's own `justification` text puts the size argument
  first and the rule in a separate field, so that input invites the error. Flash left the verdict out in 5/6 runs,
  which this check scores as a minor issue. In the one Flash run that stated it (03_flash), Flash gave the same wrong
  reason ("smaller than one decibel").
- On the NIOSH trips: Argon left out that the two trips were on different trains in 6/6 runs; Flash did so in at least
  5/6 (the `07_flash` note records only the missing 85 dB(A) limit, so that run is not counted here). Both models, in
  4-6 of 6 runs, stated absence from 14 documents as absence from "the public record".

**What this means for "why Argon?"** The verifier pass rate and speed do not support it. What Argon does is read more
of the long corpus into the pack and connect documents. About half of its major framing errors (9 of 17, as judged by
one unblinded judge) came from joining two documents; the rest were a verdict given for the wrong reason (6) and a
non-committal answer turned into a commitment (2). The deterministic verifier cannot see any of these (every one of
these claims passed it). If the pitch
claims Argon, the honest version is "Argon pulls more of the record together; that is why the pack still needs an
independent review and the human approval", not "Argon is more accurate". A fair "Flash is enough" reading is also
available: for a pack that only needs the core facts (grinding list, cab figures, 92.8 provenance), Flash covered them
with fewer and milder framing errors (same caveat: unblinded single judge).

**Not established.** n = 6 per model, one task and one prompt, so no significance claim. The framing check has one
judge, no effective blinding (note 3) and a checklist derived from Argon errors. Token counts are not comparable: Argon reported
thinking tokens in only 2 of 12 rounds (Flash in 11 of 12), and the two models report different prompt token counts for the
byte-identical prompt (round 0: 49,387 vs 48,435; summary table). Cost was not measured. The production pack (`investigation.json`) is an Argon draft after
two review-driven revisions. These were fresh, unreviewed runs.

**Cheap fixes these runs suggest (for the lead; not done here):** reword `loudness.verdict.detail.justification` so the
reversed trip R10 comes first; add "one trip per direction, on different trains" to the NIOSH sentence of the
investigator prompt; tell the investigator that the corpus is 14 documents and to write "in the documents reviewed".

**README-ready line (the lead decides):** Post-hoc, with 6 fresh runs per model on the same investigator task,
gemini-3.8-flash passed the deterministic verifier as well as gemini-4-argon (2 rounds, 0 claims dropped, about 110 s
each). Argon cited about twice as many passages (median 13 vs 6 chunks, 9 vs 6 documents), including the Mayor's 16 Jul
2026 promise in 5/6 runs vs 0/6. In an unblinded single-judge framing check it also made more errors (median 3 major
issues per run vs 0, and 1.00 vs 0.48 issues per claim; a similar rate per word): about half of its major issues (9 of 17) came from joining two documents,
and most of the rest (6) gave the wrong reason for the loudness NO-GO. That is why the pack still goes through an
independent review and human approval.
